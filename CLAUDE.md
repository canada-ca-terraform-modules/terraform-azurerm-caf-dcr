# Copilot / Claude instructions — terraform-azurerm-caf-dcr

This module wraps a single resource: `azurerm_monitor_data_collection_rule`. It has no
sibling resources (no private endpoint, no secret/backup/autoshutdown support) because the
underlying Azure resource needs none of those.

## Commands

```bash
terraform init -backend=false
terraform fmt -recursive
terraform validate
terraform test
```

To plan against the ESLZ example (requires real Azure resource IDs, not just mocks):

```bash
cd ESLZ && terraform init && terraform plan -var-file=DataCollectionRule.tfvars
```

## Naming convention

`{env4}-{group}-{project}-{userDefinedString}`, lowercased and stripped of any character not
matching `[0-9a-z-]`, truncated to 64 chars. Implemented in [name.tf](name.tf); resource
group name resolution (accepts either a `resource_groups` map key or a full resource ID) is
in [locals.tf](locals.tf).

## Design patterns present in this module

- Every optional top-level argument uses `try(var.dcr.<attr>, <registry_default>)`.
- Every optional single-instance block (`identity`, `data_sources`) uses a `dynamic` block
  gated by `try(var.dcr.<block>, null) != null ? [1] : []`.
- Every multi-instance destination/data-source block (`log_analytics`, `syslog`,
  `performance_counter`, etc.) is keyed by a map under `var.dcr.destinations` /
  `var.dcr.data_sources`, where the map key becomes the block's `name` attribute.
- `data_flow` is a required list (not a map) since duplicate entries are legal; it's iterated
  via `{ for idx, flow in var.dcr.data_flow : idx => flow }` to satisfy `dynamic`'s for_each
  requirement.
- `tags = merge(var.tags, try(var.dcr.tags, {}))` — never invent tags, always merge the
  caller's.

## Agent guidance checklist

- Read `variables.tf` → `locals.tf` → the target file before editing.
- Check `ESLZ/DataCollectionRule.tf` before changing this module's variable interface — it's
  copied verbatim into consuming ESLZ blueprints and must stay in sync.
- Check naming side-effects before changing how `env`/`group`/`project`/`userDefinedString`
  are combined — any change here changes every existing rule's Azure resource name.
- Keep edits outside the `<!-- BEGIN_TF_DOCS -->` / `<!-- END_TF_DOCS -->` markers in
  `README.md` — that section is regenerated by CI.
- Run `terraform fmt -recursive` after any `.tf` edit.
- Add a new `run` block to `tests/dcr.tftest.hcl` for any new optional argument/block.
